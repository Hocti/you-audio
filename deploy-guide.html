You Audio 部署手冊

三件事：更新手機 app、喺本機開 backend 試、更新 NAS 上嘅 backend 而唔搞爛資料。

  • A. 更新手機 app（USB）
  • B. 本機開 backend 試
  • C. 更新 NAS Docker backend
  • D. 速查 + 更新前檢查表

A. 更新手機 app（USB 直連）

用 build version 推新版本落 USB 直連嘅 Android。同一部電腦、同一個 package build 出嚟嘅 APK 會直接覆蓋安裝，設定同已下載音檔全部保留。

版本號已經自動化

build.gradle 已改成讀 pubspec.yaml 嘅 version: X.Y.Z+N（+ 後面就係 Android versionCode），而 make apk / make install 每次 build 之前都會自動升 —— 1.1.1+3 → 1.1.2+4。唔需要再手改版本號。

實測驗證過：pubspec 1.1.1+3 build 出嚟嘅 APK 係 versionCode=3 versionName=1.1.1。

  1. 開手機嘅 USB 除錯。 設定 → 關於手機 → 連按 7 次「版本號碼」→ 返設定 → 系統 → 開發者選項 → 開 USB 除錯。駁線後手機會彈「允許 USB 除錯嗎？」，要按允許。
  2. 確認電腦見到部機。
    電腦 · 任何目錄
    adb devices
flutter devices
    adb devices 要見到一行 device（唔係 unauthorized、唔係空白）。空白就：換線、換 USB 口、手機通知欄嘅 USB 模式揀「檔案傳輸／MTP」，再 adb kill-server && adb devices。
  3. 升版號 + build + 裝，一句過。
    電腦 · youtube-audio/flutter_app
    cd flutter_app
make install
    make install 做三件事：tool/bump_version.sh 升 pubspec 版號 → flutter build apk --release → adb install -r。-r 就係「覆蓋安裝、保留資料」。
    指令做咩
    make version睇現時版號
    make bump只升版號，唔 build（1.1.1+3 → 1.1.2+4）
    make apk升版號 + build，唔裝（想留 APK 檔俾其他機）
    make install升版號 + build + 裝落 USB 部機
    make run邊跑邊睇 log，唔升版號
    唔好用 flutter install

    佢唔會 build。查過 flutter tool 原始碼（android/application_package.dart）：見到 app-release.apk 已經存在，就直接讀嗰個舊檔嘅資料然後裝落機 —— 你改嘅 code 根本冇入去。一定要先 flutter build apk。

  4. 確認裝到新版。
    電腦 · 任何目錄
    adb shell dumpsys package net.teashop.you_audio | grep -E "versionCode|versionName"
    versionCode 應該同 make version 顯示嘅 +N 一樣。想直接驗 APK 檔本身：
    電腦 · youtube-audio/flutter_app
    $ANDROID_HOME/build-tools/35.0.0/aapt dump badging \
  build/app/outputs/flutter-apk/app-release.apk | head -1

裝唔到嘅時候

錯誤意思做法
INSTALL_FAILED_VERSION_DOWNGRADE新 APK 嘅 versionCode 比機上細升高 versionCode 再 build
INSTALL_FAILED_UPDATE_INCOMPATIBLE
signatures do not match		簽名唔同（見下面）要先反安裝，會清資料
no devices foundadb 見唔到部機回第 2 步
簽名陷阱 — 換電腦會清光資料

build.gradle 嘅 release build 用 signingConfigs.debug，即係用 ~/.android/debug.keystore 簽名，而呢個 keystore 每部電腦都唔同。

  • 同一部電腦 build → 簽名一樣 → 覆蓋安裝，資料全保留。
  • 換咗電腦（或重裝系統、刪過 ~/.android）→ 簽名唔同 → Android 拒絕覆蓋，一定要 adb uninstall net.teashop.you_audio，而咁做會清走 server URL、token、播放進度、以及所有已下載嘅音檔同字幕。

避免方法：永遠喺同一部機出 build，並且 backup ~/.android/debug.keystore；或者建立一個固定嘅 release keystore。

正常更新會保留

Server URL 同 token、每首歌嘅播放進度／已聽標記、字幕自動 scroll 開關、書籤頻道（全部喺 SharedPreferences），加上 library/ 底下嘅 mp3／縮圖／字幕檔 —— 覆蓋安裝一律唔會動。

B. 本機開 backend 試

make run 用 SQLite 同本機資料夾，完全唔會碰 NAS 上嘅 Postgres 同音檔 —— 兩個獨立資料庫，隨便試。

  1. 裝好依賴。本機模式唔用 Docker，所以 Python 3.11+ 同 ffmpeg 要自己有。
    電腦 · youtube-audio/backend
    cd backend
make venv                   # 一次性：建 .venv 並裝好依賴
ffmpeg -version | head -1   # 確認 ffmpeg 裝好

    make venv 之後，make run 同 make test 會自動用 .venv（Makefile 見到 .venv/bin/python 存在就用佢，冇就用 python3）。

    唔好裝入 conda base

    將 server 依賴 pip install 入一個共用環境（例如有 gradio 嘅 conda base），兩邊會爭 fastapi／starlette／python-multipart 嘅版本。pip 會照裝，但同時靜靜雞搞壞另一邊：

    gradio 6.15.2 requires fastapi<1.0,>=0.115.2, but you have fastapi 0.111.0

    呢句係安裝成功之後嘅衝突報告，唔係安裝失敗。但意思係 gradio 而家壞了。用 make venv 隔離，然後喺 base 執行 pip install -U gradio 修返 gradio。

    兩個已修好嘅 requirements.txt 問題
    • No matching distribution found for yt-dlp-ejs — yt-dlp-ejs 用 semver（最新 0.8.0），唔係 yt-dlp 嘅日期版本號，所以舊寫法 >=2026.6.9 永遠解析唔到。呢個亦會令 Docker image build 失敗。
    • Failed building wheel for pydantic-core / asyncpg — Python 3.13 冇對應 wheel，pip 退回由 source 編譯（要 Rust／C toolchain）就爆。已升 asyncpg==0.31.0、pydantic==2.8.2（各自第一個有 cp313 wheel 嘅版本）。

    兩個都 git pull 就有。更新 NAS 之前一定要有呢兩個修正。

  2. 準備 .env。make run 會從 .env 撈 YOUTUBE_API_KEY（頻道功能要用）。冇就由範本複製：
    電腦 · youtube-audio/backend
    cp .env.example .env
# 然後編輯 .env，填 YOUTUBE_API_KEY
  3. 開機。
    電腦 · youtube-audio/backend
    make run
    會由 .env 讀 ACCESS_TOKEN 同 YOUTUBE_API_KEY，用 SQLite ./ytaudio.db、檔案放 ./data、聽 0.0.0.0:8000，並且 --reload（改 code 自動重啟）。Ctrl-C 收工。App Settings 入嘅 token 就係 .env 裡面嗰個。
    改 .env 個 token 就會生效

    ACCESS_TOKEN 而家係權威：每次開機都會令 admin 用戶嘅 token 對齊 .env（唔存在就建，唔一樣就改）。所以改完 .env 重啟就得，唔需要碰資料庫。

    以前係「已存在就永不覆蓋」，結果一旦冇帶 ACCESS_TOKEN 開過一次機，就會卡死喺一個隨機 token（log 印過嗰個），之後點設 .env 都無效 —— 呢個已經修好。

    .env 留空 ACCESS_TOKEN 嘅話，第一次開機會隨機生成並印喺畫面，之後唔會再變：

    WARNING  Seeded default admin user with generated token: xxxxxxxxxxxx
  4. 驗證。
    電腦 · 另開一個 terminal
    TOKEN=$(grep -E '^ACCESS_TOKEN=' .env | cut -d= -f2-)
curl http://localhost:8000/api/health
curl -H "X-Access-Token: $TOKEN" http://localhost:8000/api/yt-dlp/version
curl -H "X-Access-Token: $TOKEN" http://localhost:8000/api/videos | head -c 200
    第一句永遠 200，token_valid 話你 token 對唔對。第二句報 backend 實際載入緊嘅 yt-dlp 版本。第三句應該列得出已下載嘅片；如果 500 就睇一睇 log 有冇 no such column（正常情況下開機會自動補欄位）。
  5. 用手機連本機。手機唔識 localhost，要用電腦內網 IP，兩邊同一個 Wi-Fi。
    電腦 · 拎內網 IP
    hostname -I | awk '{print $1}'
    喺 app Settings 入 http://192.168.x.x:8000 同 token，撳 Test 掣驗證。App 已准許 cleartext HTTP，唔需要 HTTPS。連唔到就檢查電腦防火牆放唔放 8000。
  6. 跑測試（改過 code 就跑）。
    電腦 · youtube-audio/backend
    python -m pytest -q
    用臨時 SQLite，唔會影響 ytaudio.db。

C. 更新 NAS Docker backend（保留資料）

資料庫同已下載音檔住喺兩個 named volume（pgdata 同 ytdata）。只要唔刪 volume，重建 image 同重啟 container 都唔會掉資料。

絕對唔可以做
  • docker compose down -v — -v 就係「連 volume 一齊刪」，音檔同資料庫即時清光。要停就用冇 -v 嘅 docker compose down。
  • docker volume rm ... 或 docker system prune --volumes。
  • 喺 Container Manager 刪 Project 時勾「同時刪除 volume／資料」。
今次更新有 breaking change：驗證由「無」變「必須」

舊版只喺 ACCESS_TOKEN 非空時才檢查 token，而 docker-compose.yml 現時係 ACCESS_TOKEN: "" —— 即係而家根本冇驗證。新版每個 request 都要一個對得上 users 表嘅 token（只有 /api/health 例外）。

唔理嘅話，更新完 app 會全部 401。所以更新前要喺 docker-compose.yml 填好 token（第 3 步），再喺 app Settings 入同一個。

好消息：ACCESS_TOKEN 而家係權威，每次開機都會令 admin 嘅 token 對齊。即係萬一你已經用空 token 開過機、admin 拎咗個隨機 token，只要填好 ACCESS_TOKEN 再 docker compose up -d 就會改返，唔需要進 DB 改。

  1. 先備份（唔准跳）。
    NAS · SSH · project 目錄
    cd /volume1/docker/youtube-audio-backend
docker compose exec -T db pg_dump -U ytaudio ytaudio > ~/ytaudio-db-$(date +%F).sql
ls -lh ~/ytaudio-db-*.sql
    音檔喺 volume 度，重建 image 唔會影響佢；想連檔一齊備份就 tar 走個 volume：
    NAS · SSH · 選擇性、可能好大
    docker volume ls | grep ytdata   # 先確認實際 volume 名
sudo tar czf ~/ytdata-$(date +%F).tar.gz \
  -C /volume1/@docker/volumes/youtube-audio-backend_ytdata/_data .
    Volume 名點嚟

    Docker 用目錄名做 project 前綴，所以真名可能係 backend_ytdata、youtube-audio-backend_ytdata 或其他。永遠用 docker volume ls 睇實際名，唔好照抄。

  2. 更新原始碼。如果 NAS 上係 git clone：
    NAS · SSH · project 目錄
    git pull
    如果係用 scp／File Station 傳上去，就喺你電腦 push 新版，但唔好覆蓋 docker-compose.yml（嗰個檔有你 NAS 專屬設定）：
    電腦 · youtube-audio
    scp -r backend/app backend/requirements.txt \
    backend/Dockerfile backend/entrypoint.sh \
    你嘅帳號@NAS_IP:/volume1/docker/youtube-audio-backend/
  3. 補齊環境變數。docker-compose.yml 嘅 backend 服務要有以下四個。ACCESS_TOKEN 見上面嘅 breaking change；YOUTUBE_API_KEY 目前完全冇喺 compose 檔裡面，冇佢頻道瀏覽會 500。
    編輯 · NAS 上嘅 docker-compose.yml
    environment:
  DATABASE_URL: "postgresql+asyncpg://ytaudio:ytaudio@db:5432/ytaudio"
  DATA_DIR: "/data"
  ACCESS_TOKEN: "填一個你自己嘅長密碼"   # 只喺第一次 seed admin 時用
  YOUTUBE_API_KEY: "你嘅 YouTube Data API v3 key"
  4. 重建同重啟。
    NAS · SSH · project 目錄
    docker compose build backend
docker compose up -d
    up -d 只重建有改動嘅 container，volume 原封不動。Postgres 個 container 通常連重啟都唔需要。
  5. 確認資料庫欄位補齊（現在自動）。 create_all 只會建新表（users、requests 會自動出現），唔會幫已存在嘅表加新 column —— 所以舊 DB 一升級，/api/videos 就會 500 話 no such column: videos.channel_id。現在開機會自動跑 ensure_columns() 補齊，log 會見到： 
    WARNING  Added missing column videos.channel_id
    要親自核對：
    NAS · SSH · project 目錄
    docker compose exec -T db psql -U ytaudio -d ytaudio -c "\d videos"
    萬一自動補失敗，手動嗰句係（Postgres 版本；SQLite 唔支援 IF NOT EXISTS）：
    NAS · SSH · 只在需要時
    docker compose exec -T db psql -U ytaudio -d ytaudio \
  -c "ALTER TABLE videos ADD COLUMN IF NOT EXISTS channel_id TEXT;"
  6. 睇 log 確認。
    NAS · SSH · project 目錄
    docker compose logs -f backend
    要見到 [entrypoint] Upgrading yt-dlp to latest...、[entrypoint] yt-dlp 2026.xx.xx、Database tables ensured.。如果 ACCESS_TOKEN 留空，呢度會印出隨機生成嘅 admin token —— 抄咗佢入 app。
  7. 驗證舊資料仲在。
    電腦 · 換成你嘅 NAS IP 同 token
    curl http://NAS_IP:8000/api/health
curl -H "X-Access-Token: 你嘅token" http://NAS_IP:8000/api/videos | head -c 400
curl -H "X-Access-Token: 你嘅token" http://NAS_IP:8000/api/yt-dlp/version
    /api/videos 要仍然列出更新前嗰批片。之後開 app 撳 Settings 嘅 Test 掣做最後確認。

更新後想單獨升 yt-dlp

唔需要再重啟容器 —— 新增咗一個 admin 專用 endpoint，一 call 就升級並熱重載：

瀏覽器或 curl · 要 admin token
curl -H "X-Access-Token: 你嘅admin token" http://NAS_IP:8000/api/yt-dlp/update

回覆會有 previous_version、current_version、reloaded。如果當時有下載進行中，重載會延後並回 restart_required: true —— 等下載完再 call 一次，或者重啟容器。

要回滾

NAS · SSH · project 目錄
git checkout <舊嘅 commit>
docker compose build backend
docker compose up -d

Volume 唔受影響，所以音檔同資料庫照舊。真係要還原資料庫先 psql -U ytaudio -d ytaudio -f ~/ytaudio-db-YYYY-MM-DD.sql。

更新 NAS 前逐項打勾

  • ☐ pg_dump 備份做完，檔案大細唔係 0
  • ☐ docker-compose.yml 已填 ACCESS_TOKEN 同 YOUTUBE_API_KEY
  • ☐ 指令裡面完全冇 -v 或 --volumes
  • ☐ 已 git pull 到修好 yt-dlp-ejs 版本號嘅版本（唔然 image build 會失敗）
  • ☐ Log 見到 Added missing column，或者 \d videos 見到 channel_id
  • ☐ /api/videos 仍然列得出更新前嗰批片
  • ☐ App Settings 嘅 Test 掣顯示 token 有效
